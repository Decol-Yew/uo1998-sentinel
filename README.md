# uo1998-sentinel

UO:1998 シャード用の **ステータス監視ツール**（Windows）。

**HP / マナ / スタミナ / 所持重量** を受信パケットから監視し、設定した**閾値に達したら
WAV を鳴らし、キーを送信**します。キー送信で **AutoHotkey** を起動できます
（例：マナが満タンになったら AHK のマクロを走らせる）。

> **通信経路には一切割り込みません。** 自分のPCが受け取るパケットを横から読み取るだけで、
> 改変もサーバーへの送信もしないため、ツールが原因でゲーム接続が切れること（コネロス）は
> ありません。姉妹ツールの翻訳ツール
> [uo1998-translator](https://github.com/Decol-Yew/uo1998-translator) と**同じパッシブ
> キャプチャ**方式で、**同時起動**もできます（それぞれ独立に受信を観測します）。

---

## できること

- **4ステータス監視**：HP / マナ / スタミナ / 所持重量 を受信から読み取り、現在値を表示。
- **閾値アラーム**：`>=`（以上）/ `<=`（以下）× `値`（そのもの）/ `%`（最大に対する割合）で指定。
  - 例）マナ `>=` `90` `%` … マナが最大の90%を超えた瞬間に通知。
  - 例）HP `<=` `30` `%` … HPが30%以下に落ちた瞬間に警告。
  - 例）マナ `>=` `40` `値` … マナが40に達した瞬間に通知。
  - 「現在値」欄は常に `現在/最大 (NN%)` と割合も併記されます。
- **WAV 再生**：鳴らす音を各行ごとに指定（`…`で選択、`▶`で試聴）。
- **キー送信（AHK連携）**：閾値到達時に任意のキーを送出。**F13〜F24 推奨**
  （ゲームは無視し、AHK のグローバルホットキーが拾いやすい／フォーカスを奪いません）。
- **連打防止**：一度鳴ったら条件を外れるまで再発火しません（ヒステリシス）。
- **設定の記憶**：監視ルールとウィンドウ位置を `sentinel_state.json` に保存し、次回復元。

## 必要なもの

- Windows + **Python 3.11〜3.14**（https://www.python.org ／インストール時「Add to PATH」にチェック）
  - Sentinel は scapy だけに依存する軽い構成なので、翻訳ツールのような新しめ Python の
    相性問題（pydantic_core / jiter）はありません。
- **Npcap**（パケットキャプチャ用ドライバ）… https://npcap.com
  - インストール時に「**Install Npcap in WinPcap API-compatible Mode**」にチェック
- UO:1998 のクライアント一式
- （任意）**AutoHotkey** … キー送信からマクロを走らせたい場合

> キャプチャには**管理者権限**が必要です。`run.bat` は自動で昇格（UACの確認）します。

## セットアップ（初回のみ）

1. **Npcap をインストール**（上記、WinPcap互換モードにチェック）
2. この一式をフォルダに置く（GitHubの「Code → Download ZIP」でも可）
3. **`setup.bat` をダブルクリック** … 仮想環境の作成・依存導入・`config.ini` 作成まで自動
4. **`config.ini`** をメモ帳などで開いて設定：
   - `[capture] iface` = ネットに繋がっている回線名（例 `Wi-Fi`）。**空欄なら自動選択**
   - `[filter] self_names` = 自分のキャラ名（誰のステータスを見るかの判別に使用）

> 翻訳ツールと**同じ `config.ini`** を使えます。翻訳ツールの config.ini があるフォルダで
> 実行すれば、`[capture]`/`[filter]` の設定をそのまま共有できます。

## 使い方

1. **`run.bat` をダブルクリック** → 管理者権限の確認（UAC）に「はい」→「UO:1998 Sentinel」ウィンドウが最前面に出る
2. **クライアントを起動してログイン** → ゲームにIN
   - 既にログイン済みのときは、**一度ログインし直す**と確実です（接続の先頭から読み取るため）
   - **キャラクターを変更したとき**は、ゲームに入り直せば新規接続を検出して**自動で自分を取り直し**ます。
     自動で切り替わらない場合は、画面右上の **「キャラ再検出」** ボタンを押してください。
3. 本体の各行の「監視」チェックで有効化。条件・閾値・WAV・キーは **「設定…」** ボタンで編集
4. 閾値に達すると WAV が鳴り、指定キーが送出されます

### 画面（本体はコンパクトなライブ表示）

UOクライアント左右の黒い余白に並べて置けるよう、本体は**細い縦長**で、ライブ表示だけにしています。

4行（HP / マナ / スタミナ / 重量）それぞれに：

| 列 | 意味 |
|---|---|
| チェック＋ラベル | この行の監視ON/OFF（クリックで即切替） |
| 現在値 | いまの `現在/最大 (NN%)`（割合も常時併記）。**残量に応じて緑/黄/赤に色分け**（UOAssist風） |
| しきい値 | 設定中の条件を短縮表示（例 `≥90%` / `≤30` / `≥40`） |

**色分け**：残量（%）が `color_green` 以上で**緑**、`color_yellow` 以上で**黄**、それ未満で**赤**。
既定は 緑 `68` / 黄 `35`（`config.ini [filter]` で変更可）。HP/マナ/スタミナは残量、
重量は「残り容量（=100−積載率）」で判定するので、**満杯・過積載に近づくと赤**になります。

上部に **「設定…」**（条件・閾値・WAV・キーの編集ダイアログを開く）と
**「キャラ再検出」** ボタンがあります。

**ウィンドウ操作**：
- **前回のサイズ・位置を保存**し、次回起動時に復元します。
- **ダブルクリック**で**タイトルバーの表示/非表示を切替**（UOAM風。非表示のほうがすっきり並べられます）。
  タイトルバー非表示のときは、**見出し/空き領域をドラッグして移動**できます。閉じる/最小化したいときは
  もう一度ダブルクリックしてタイトルバーを戻してください。この表示状態も次回に引き継がれます。

#### 「設定…」ダイアログ

| 列 | 意味 |
|---|---|
| 監視 | この行を有効にするチェック |
| 条件 | `>=`（以上）/ `<=`（以下） |
| 閾値 | 数値 |
| 値/% | `値`=値そのもの / `%`=最大に対する割合 |
| WAV | 鳴らす音（`…`で選択、`▶`で試聴） |
| キー | 送るキー（例 `F13`）。空なら送らない |

変更は即時に本体へ反映され、「閉じる」で保存されます。

### 重量について
所持重量（現在値）は `0x11` ステータスパケットで届きます（HP/マナ/スタミナのような
増分専用パケットは無い）。一方 **最大重量はサーバーが送りません**（1998仕様の
`0x11 type=1` には最大重量フィールドが無い）。そのため最大重量は**こちらで算出**します。

このシャードの最大重量は **ベースSTR** で決まり、**ブレス魔法や STR ポーションの一時STRでは
増えません**（このサーバーはステータスロックが無く、スキル使用でSTRが頻繁に変動します）。
実測較正した式は **`最大重量 = STR×4 + 30`**（STR59→266 / STR60→270 / STR93→402 が一致）。
`config.ini [filter]` で指定できます：

| 設定 | 動作 |
|---|---|
| `max_weight = N` | 最大重量を **固定値 N** にする（ゲーム内で実測した上限を入れるのが最も確実・推奨） |
| `base_str = N`   | `N × 4 + 30` で算出（無バフ時のベースSTRを入れる） |
| 両方 `0`（既定）  | 受信STR（現在値）から `STR × 4 + 30` で算出（**バフ/スキルでSTRが動くと実際と差が出る**） |

現在値と最大は監視画面の「重量」行に `現在/最大` で表示されます。`%`（割合）監視を使うなら、
上の設定で最大重量を正しくしておくと精度が上がります（重量は `値` 監視も確実）。

## AutoHotkey 連携

「キー」に **F13〜F24** を指定するのがおすすめです（ゲームは無視し、AHK が拾いやすい）。
キー送信はフォーカスを奪いません（AHK のグローバルホットキーを叩くだけ）。

AHK 側の例：

```ahk
; マナ監視でキー「F13」を送った時に実行される
F13::
    SoundBeep 1000, 200
    ; 例: 特定キーを押す / クリックする 等、好きな操作
return
```

監視ツールの「キー」欄に `F13` を入れておけば、閾値到達時に AHK の `F13::` が走ります。

## 安全性・プライバシー

このツールは**すべて人間が読めるPythonスクリプト**で、難読化コードは含みません。

- **自分のPCが受け取る通信を、ローカルで観測するだけ**です（Npcapによるパケットキャプチャ）。
  通信経路に割り込んだり、パケットを書き換えたり、サーバーへ送信したりは**しません**。
- 読み取るのは**サーバー→クライアント方向のステータス情報のみ**。パスワード等の
  ログイン情報（クライアント→サーバー方向）は暗号化されており、**復号しません**。
- 外部送信は一切ありません（監視はすべてローカルで完結）。

### しくみ（技術メモ）
- Npcap + Scapy でゲーム接続（TCP :2593）の **サーバー→クライアント方向**を捕捉。
- TCPハンドシェイク(SYN-ACK)で接続の先頭を掴み、受信ストリームを順序どおり再構成
  → Huffman 解凍 → パケット分解 → `0x11`/`0x2D`/`0xA1`/`0xA2`/`0xA3`（ステータス系）を抽出。
- 受信下層（`capture.py` / `uo_huffman.py` / `uo_packets.py` / `keysend.py`）は翻訳ツールと
  共通の実装です（本リポジトリはそのコピーを同梱）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `sentinel.py` | GUI 本体（4ステータス監視・閾値判定・WAV/キー送出） |
| `uo_stats.py` | 受信からHP/マナ/スタミナ/重量を抽出するスキャナ |
| `capture.py` | **受信キャプチャ**（Npcap+Scapy で観測→TCP再構成。経路に割り込まない） |
| `uo_huffman.py` | 受信の Huffman 解凍（ServUO 由来テーブル） |
| `uo_packets.py` | パケット長テーブル＋解析（ClassicUO 由来・1.25.32 用） |
| `keysend.py` | キー送出（`send_vk` で F13〜F24 等を送る。フォーカスを奪わない） |
| `config.ini.example` | 設定の雛形（実設定 `config.ini` は Git 管理外） |
| `setup.bat` / `run.bat` | セットアップ / 起動（run.bat は管理者へ自動昇格） |
| `build.bat` | 単体 exe 化（UO1998Sentinel.exe） |
